# Инцидент 2: ошибка прав доступа — 403 Forbidden

## Цель

Проверить ситуацию, когда nginx запущен, конфигурация корректная, порт 80 слушается, но сайт не открывается из-за прав доступа к файлу.

## Что было сломано

У файла главной страницы сайта были намеренно забраны все права:

```bash
sudo chmod 000 /var/www/site01/index.html
```

После этого файл стал недоступен для чтения.

Проверка прав:

```bash
ls -l /var/www/site01/index.html
```

Ожидаемый результат:

```text
---------- 1 root root ... index.html
```

## Симптом

При обращении к сайту nginx вернул ошибку:

```text
HTTP/1.1 403 Forbidden
```

Проверка выполнялась командой:

```bash
curl -i -H "Host: rhodesian-lab.test" http://127.0.0.1/
```

## Диагностика

Для диагностики использовались команды:

```bash
curl -i -H "Host: rhodesian-lab.test" http://127.0.0.1/
```

Проверка HTTP-ответа от nginx.

```bash
tail -n 20 /var/log/nginx/error.log
```

Просмотр ошибок nginx.

```bash
ls -l /var/www/site01/index.html
```

Проверка прав на файл.

```bash
ls -ld /var/www/site01
```

Проверка прав на директорию сайта.

## Что было видно в логах

В `error.log` nginx была ошибка вида:

```text
permission denied
```

Это означает, что nginx не смог прочитать файл из-за прав доступа.

## Причина

Nginx нашёл нужный файл `index.html`, но не имел прав его прочитать.

Это отличается от ошибки `404 Not Found`: при `403` файл существует, но доступ к нему запрещён.

## Исправление

Права на файл были восстановлены:

```bash
sudo chmod 644 /var/www/site01/index.html
```

После этого файл снова стал доступен для чтения.

Проверка:

```bash
ls -l /var/www/site01/index.html
```

Ожидаемый вид прав:

```text
-rw-r--r--
```

## Проверка после исправления

После исправления был снова выполнен запрос:

```bash
curl -i -H "Host: rhodesian-lab.test" http://127.0.0.1/
```

Ожидаемый результат:

```text
HTTP/1.1 200 OK
```

## Вывод

Ошибка `403 Forbidden` часто связана с правами доступа.

В этом инциденте nginx видел файл `index.html`, но не мог его прочитать из-за прав `000`.

Для диагностики полезны команды:

```bash
curl -i -H "Host: rhodesian-lab.test" http://127.0.0.1/
tail -n 20 /var/log/nginx/error.log
ls -l /var/www/site01/index.html
ls -ld /var/www/site01
```

Не стоит исправлять такие проблемы через `chmod 777` без необходимости. Лучше сначала понять, каких именно прав не хватает, и выдать минимально необходимые права.
