# Инцидент 1: ошибка в конфигурации nginx

## Цель

Проверить, как диагностировать ситуацию, когда nginx не может применить конфигурацию из-за синтаксической ошибки в конфиге.

## Что было сломано

В конфиге сайта:

```text
/etc/nginx/sites-available/site01.conf
```

была намеренно допущена ошибка в директиве `server_name`.

Например, была убрана точка с запятой `;` в конце строки:

```nginx
server_name rhodesian-lab.test
```

Правильный вариант:

```nginx
server_name rhodesian-lab.test;
```

## Симптом

После проверки конфигурации nginx показал ошибку:

```bash
sudo nginx -t
```

Конфигурация не прошла проверку, поэтому nginx не мог корректно применить изменения.

## Диагностика

Для диагностики использовались команды:

```bash
sudo nginx -t
```

Проверка синтаксиса конфигурации nginx.

```bash
systemctl status nginx --no-pager -l
```

Проверка текущего состояния сервиса nginx.

```bash
journalctl -u nginx -n 30 --no-pager
```

Просмотр последних логов systemd-unit nginx.

## Что означает `nginx -t`

Команда:

```bash
sudo nginx -t
```

проверяет конфигурацию nginx на синтаксические ошибки.

Если всё хорошо, nginx выводит:

```text
syntax is ok
test is successful
```

Если в конфиге есть ошибка, nginx показывает файл и строку, где обнаружена проблема.

## Что означает `systemctl status nginx --no-pager -l`

Команда:

```bash
systemctl status nginx --no-pager -l
```

показывает текущее состояние сервиса nginx:

- `active (running)` — сервис работает;
- `failed` — сервис упал или не смог запуститься;
- `inactive` — сервис остановлен.

Параметр `--no-pager` выводит результат сразу в терминал, без открытия просмотрщика `less`.

Параметр `-l` показывает длинные строки полностью.

## Что означает `journalctl -u nginx -n 30 --no-pager`

Команда:

```bash
journalctl -u nginx -n 30 --no-pager
```

показывает последние 30 записей логов для сервиса nginx.

Разбор:

```text
journalctl — просмотр логов systemd
-u nginx — показать логи только unit/service nginx
-n 30 — последние 30 строк
--no-pager — вывести сразу в терминал
```

## Причина

Причиной была синтаксическая ошибка в конфигурационном файле nginx.

Nginx чувствителен к синтаксису: директивы обычно должны заканчиваться символом `;`.

## Исправление

Ошибка была исправлена: в конфиг была возвращена точка с запятой.

После этого была выполнена проверка:

```bash
sudo nginx -t
```

Затем конфигурация была применена:

```bash
sudo systemctl reload nginx
```

## Проверка после исправления

После исправления nginx снова успешно прошёл проверку:

```text
syntax is ok
test is successful
```

Сервис был проверен командой:

```bash
systemctl status nginx --no-pager -l
```

Также был проверен HTTP-ответ:

```bash
curl -i -H "Host: rhodesian-lab.test" http://127.0.0.1/
```

## Вывод

Если nginx не применяет конфигурацию или не стартует после изменений, первым делом нужно выполнить:

```bash
sudo nginx -t
```

Эта команда помогает быстро найти синтаксические ошибки в конфиге.

Правильный порядок после изменения nginx-конфигов:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Если сервис не работает, дополнительно смотреть:

```bash
systemctl status nginx --no-pager -l
journalctl -u nginx -n 30 --no-pager
```
